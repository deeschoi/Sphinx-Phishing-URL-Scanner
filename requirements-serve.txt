# Runtime packages for the Vercel function. Training and research stay in
# requirements.txt (matplotlib, statsmodels, mlxtend, kmodes, python-whois,
# lightgbm, shap). Docker and CI keep installing that file.
#
# xgboost-cpu==2.1.4 is not on PyPI (CPU builds start at 3.0.0). The 2.1.4
# Linux wheel links libnccl.so.2. The nvidia-nccl-cu12 wheel that provides it
# is 182MB compressed at 2.22.3 and 308MB at 2.27.7, which on its own blows
# the function budget. The deploy workflow trains with THIS file so the
# pickled booster matches the runtime. Docker keeps training with
# xgboost==2.1.4 from requirements.txt.
#
# scikit-learn 1.9.1 publishes manylinux_2_27/2_28 wheels, not manylinux2014.
# Vercel's build image is Amazon Linux 2023 (glibc 2.34), so those wheels
# install there and on ubuntu-latest. Do not run `vercel build` on macOS:
# the CLI would vendor host wheels the function cannot load.
# Unzipped manylinux_2_28 wheels, including dependencies: about 320 MiB.
# With the custom install command, the builder's default cap is 225 MB.
# The deploy sets VERCEL_SUPPORT_LARGE_FUNCTIONS=1 (limit 5 GB). The
# post-build check still fails the bundle above 500 MiB so the NCCL wheel
# cannot slip back in.
