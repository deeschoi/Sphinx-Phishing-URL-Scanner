# Runtime packages for the Vercel function. Training and research stay in
# requirements.txt (pandas, scikit-learn, matplotlib, statsmodels, mlxtend,
# kmodes, python-whois, lightgbm, shap). Docker and CI keep installing that
# file; the deploy job trains from requirements-train-serve.txt.
#
# The served model is native XGBoost (artifacts/*.ubj plus model_meta.json),
# so the function needs neither scikit-learn (to unpickle XGBClassifier) nor
# pandas. Do not add them back: xgboost imports both opportunistically when
# installed, which costs about 0.9 s on every cold start.
# tests/test_model_artifact.py scans with them blocked.
#
# xgboost-cpu==2.1.4 is not on PyPI (CPU builds start at 3.0.0). The 2.1.4
# Linux wheel links libnccl.so.2. The nvidia-nccl-cu12 wheel that provides it
# is 182MB compressed at 2.22.3 and 308MB at 2.27.7, which on its own blows
# the function budget. Native .ubj files load across xgboost versions, so a
# model trained by xgboost 2.1.4 in Docker also loads here.
#
# Do not run `vercel build` on macOS: the CLI would vendor host wheels the
# function cannot load. The deploy sets VERCEL_SUPPORT_LARGE_FUNCTIONS=1;
# measure the bundle (scripts/check_function_bundle.py) before dropping it.
#
# pyproject.toml reads its dependencies from this file and the Vercel
# builder installs them from uv.lock. Run `uv lock` after any change here.
# Do not add an Install Command: `pip install -r` fills a local venv that a
# large function never ships. scripts/check_function_bundle.py fails the
# deploy on an Install Command or an NVIDIA/NCCL wheel in uv.lock.
